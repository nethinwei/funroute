# 终止性与表达力

FunRoute 刻意**不是**图灵完备的。本文给出三条结论及其证明，并说明为什么这对支付路由是正确的取舍：

- **定理 A（强正规化）**：任何通过类型检查的程序，在任意输入上都在有限步内终止。
- **定理 B（多项式界）**：每个程序的求值步数有输入规模的多项式上界，次数由该程序的循环嵌套深度决定——延迟是可预测的。
- **定理 C（表达力边界）**：语言恰好不能表达需要无界搜索的函数（μ-递归中的 μ 算子）。要图灵完备，只需加一个无界循环构造；附录给出构造，以及不要它的原因。

---

## 1. 预备

### 1.1 语法

只取与证明相关的核心片段（完整语法见 `README.md`）：

```text
e ::= c                          字面量
    | x                          变量
    | f(e₁, …, eₙ)               函数调用（严格求值）
    | if(e₁, e₂, e₃)             条件（惰性）
    | fallback(e₁, …, eₙ)        扩展失败 / 超时级联（n ≥ 2，惰性）
    | switch(…)                  多分支（惰性）
    | [e for x in e if e]        列表推导（有限映射 / 筛选）
    | reduce(x in e if e, a = e, e)  折叠（有限，可选筛选）
```

一个**程序** P 是一个表达式；它的自由变量按首次出现顺序构成参数表。注意这里**没有**任何构造以整个程序为前提——这正是定理 A 的关键。

### 1.2 操作语义

求值关系 `ρ ⊢ e ⇓ v`（环境 ρ 下 e 求值为 v）：

```text
(LIT)   ρ ⊢ c ⇓ c
(VAR)   ρ ⊢ x ⇓ ρ(x)

(APP)   ρ ⊢ eᵢ ⇓ vᵢ  (i = 1..n)      ⟦f⟧(v₁,…,vₙ) = v
        ─────────────────────────────────────────────
        ρ ⊢ f(e₁,…,eₙ) ⇓ v

(IF-T)  ρ ⊢ e₁ ⇓ true    ρ ⊢ e₂ ⇓ v        (IF-F)  ρ ⊢ e₁ ⇓ false   ρ ⊢ e₃ ⇓ v
        ───────────────────────────────            ────────────────────────────────
        ρ ⊢ if(e₁,e₂,e₃) ⇓ v                       ρ ⊢ if(e₁,e₂,e₃) ⇓ v

(FB-OK)   ρ ⊢ e₁ ⇓ v
          ─────────────────────────
          ρ ⊢ fallback(e₁,…,eₙ) ⇓ v

(FB-NEXT) ρ ⊢ e₁ ⇑ ε   ρ ⊢ fallback(e₂,…,eₙ) ⇓ v   n > 2
          ────────────────────────────────────────────────
          ρ ⊢ fallback(e₁,…,eₙ) ⇓ v

(FB-LAST) ρ ⊢ e₁ ⇑ ε   ρ ⊢ e₂ ⇓ v
          ─────────────────────────────
          ρ ⊢ fallback(e₁,e₂) ⇓ v

          其中 ε ∈ {ErrExtension, ErrDeadline}

(FOR)   ρ ⊢ e_src ⇓ [u₁,…,u_m]     ρ[x↦uⱼ] ⊢ e_body ⇓ wⱼ  (对保留的 j)
        ──────────────────────────────────────────────────────────────
        ρ ⊢ [e_body for x in e_src if e_cond] ⇓ [w_j …]
```

`(IF)` 的前提里只出现被选中的分支——这是惰性的形式化含义。`(FB-OK)` 不求值后续候选，`(FB-NEXT)` 只在扩展失败与超时时前进一项；最后一项的错误以及任意位置的 `ErrFuel` 和表达式自身错误继续向宿主传播。候选数量来自有限语法树，所以级联必然结束。`(FOR)`/`reduce` 的前提数量等于 **已求值得到的** 数组长度 m，是一个有限值。

## 2. 定理 A：强正规化

> **定理 A.** 若所有注册的扩展函数都终止，则任何通过类型检查的 FunRoute 程序在任意输入上都终止。

*证明.* 定义度量 μ(e) = 表达式 e 的语法树节点数，考察每条规则的前提相对结论：

- (LIT)、(VAR)：无前提。
- (APP)：每个前提 eᵢ 是 e 的**真子树**，故 μ(eᵢ) < μ(f(e₁,…,eₙ))；⟦f⟧ 的求值按假设终止。
- (IF-T)/(IF-F)、(FB-OK)/(FB-ERR)：前提 e₁ 与实际选择的分支都是真子树。
- (FOR)、reduce：source 是真子树；body 被求值的次数等于 source 求值所得数组的长度 m（有限），每次求值的 body 也是真子树。

于是求值推导树满足两个性质：每条路径上 μ 严格递减，且每个节点的子节点数有限（(APP) 为 n，循环形式为 m+1）。由 König 引理，每节点有限分叉且每条路径有限的树是有限树，故求值在有限步内结束。∎

**关键之处在于语义里没有什么**：没有一条规则以整个程序 P 作为前提。这就是移除 `recur` 的意义——(REC) 那条规则是唯一能让 μ 不下降的规则，有它则定理 A 不成立。

**推论（终止性可判定）.** “这个程序会终止吗”对 FunRoute 是平凡可判定的：答案恒为是。因此 `Fuel` 不是安全必需的兜底，而纯粹是**成本上限**——它限制的是花多少，不是会不会停。

## 3. 定理 B：多项式时间上界

> **定理 B.** 对任意程序 P，存在多项式 p_P，使 P 在任意输入上的求值步数 ≤ p_P(n)，其中 n 是输入规模（所有输入数组长度之和加上标量个数）。p_P 的次数不超过 P 的循环嵌套深度加一。

*证明.* 对 P 的结构归纳，同时对“求值 e 产生的值的规模”和“求值 e 的步数”建立多项式界。

- 字面量、变量：规模与步数均为 O(1) 或 O(n)。
- (APP)：步数是各子表达式步数之和加上 ⟦f⟧ 的代价。内核函数的代价是 O(1) 或与参数规模成线性（如列表拼接），故仍是多项式；结果规模不超过参数规模之和加常数。
- (IF)、switch、fallback：步数不超过主表达式与最大分支的步数之和。
- 循环形式：设 source 求值所得数组长度为 m。由归纳假设 m ≤ q(n)（某多项式 q）。循环的步数 = m × (body 步数) + O(m)，而 body 的步数由归纳假设也是多项式，故乘积仍是多项式；结果数组长度 ≤ m。

每层循环把次数乘上一个多项式因子，因此多项式的次数随循环嵌套深度线性增长。∎

**关于凭空生成的序列**：语言里每个循环遍历的容器，要么来自输入，要么来自字面量。唯一的例外是扩展包 `extensions/std` 的 `range`，它从标量造出数组 —— 所以它的参数被要求在编译期已知（`FunctionSpec.ConstantArgs`，编译器编译该调用时检查每个实参是否只依赖常量）。于是 `range` 产出的长度是**程序文本**的一部分，对 p_P 只贡献一个常数。若允许 `range(n)` 的 n 来自参数，步数就随 n 线性增长，而输入规模只增长了 n 的位长，定理 B 当场失效 —— 这是那条限制不能松的原因。

**这是支付场景真正需要的性质**：给定一条路由规则，它的最坏延迟可以由输入规模静态地估出来，而不必依赖运行时的 fuel 计数去发现“这条规则太贵”。fuel 仍然有用（它把估算落实为硬上限），但它不再是正确性的一部分。

## 4. 定理 C：表达力边界

> **定理 C.** FunRoute 不能表达 μ-递归函数中需要 μ 算子（无界最小化）的那些，即“搜索最小的满足条件的 k”这类计算。它能表达的部分落在原始递归函数之内。

*证明.* 由定理 B，每个程序的步数有多项式上界 p_P(n)。而 μ 算子要求对任意 f 计算 μk.[f(k)=0]，其运行时间不被输入规模的任何函数界定（f 可以任意慢地到达 0）。若 FunRoute 能表达它，则存在多项式上界，矛盾。∎

反过来，定理 A 的度量论证说明所有循环次数都由**已经求得的数据**界定，这正是原始递归的形状（有界迭代）。

### 需要无界搜索时怎么办

交给扩展函数。宿主用 Go 实现，那里可以自由使用循环、超时、并发与外部服务，并由宿主为它设定自己的上界与 SLA：

```go
registry.Register(lang.FunctionSpec{
    Name:   "route.optimal_v1",
    Params: []lang.Type{lang.ArrayOf(lang.FloatType)},
    Result: lang.IntType,
    Cost:   500,                  // 迭代算法，标一个高 fuel 成本
    Eval:   optimalChannel,       // Go 侧自带迭代上限与超时
})
```

这条边界是刻意的：**语言负责可解释、可计费、有上界的决策；需要搜索的计算是一个被命名、被审查、被限时的扩展**。

## 5. 附录：如果要图灵完备

只需加一个无界循环构造。早期版本有过一个叫 `recur` 的自递归原语，下面是当时的构造性证明，保留下来是为了说明表达力不是瓶颈——不要它是取舍，不是能力缺失。

下面的 `is_empty`/`head`/`tail`/`prepend` 是这段论证假设存在的列表原语——注册表里没有它们，写出来只是为了让构造可读。

**构造**：把任意单带图灵机 M = (Q, Γ, δ, q₀, q_h) 编译成一个表达式。磁带用两个 `array<int>` 表示：r 是磁头及其右侧（磁头在首位），l 是左侧（逆序）。配置 (q, l, r) 编码为参数元组，δ 的每条规则展开成一次带新实参的重入：

```text
CUR    ≜ if(is_empty(right), 0, head(right))
TAIL_R ≜ if(is_empty(right), right, tail(right))
HEAD_L ≜ if(is_empty(left),  0, head(left))
TAIL_L ≜ if(is_empty(left),  left, tail(left))

STEP(w, R, q′) ≜ recur(⌈q′⌉, TAIL_R, prepend(w, left), add(steps, 1))
STEP(w, L, q′) ≜ recur(⌈q′⌉, prepend(HEAD_L, prepend(w, TAIL_R)), TAIL_L, add(steps, 1))

DISP(q) ≜ if(eq(CUR, 0), STEP(δ(q,0)), STEP(δ(q,1)))
⟦M⟧    ≜ if(eq(state, h), steps, if(eq(state, ⌈q₀⌉), DISP(q₀), … DISP(q_{k-1}) … ))
```

编译是机械的（规模 O(|Q|·|Γ|)），且可证明它忠实模拟 M：单步引理对 (IF)/(REC) 规则逐条核对，再对步数归纳。实测过：BB(3) 忙碌海狸编译出 191 条指令，跑出 14 步、磁带 6 个 1，与独立写的 Python 模拟器一致；不停机的机器在 5000 fuel 下被拦截。

**为什么不要它**：

1. 路由决策的真实形状是分支判断加有限遍历，`if`/`switch`/推导式/`reduce` 已经覆盖；需要迭代收敛的计算本来就该是扩展函数。
2. 它使停机不可判定，于是 fuel 从成本上限变成安全必需，定理 B 那种静态延迟估算也不再可能。
3. 它的循环变量借用程序参数，导致累加器这类**实现细节泄漏成外部参数契约**（调用方被迫传初值，传错还会静默算错）；而 `reduce` 的累加器本来就是局部的。
4. 位置绑定的实参顺序是“自由变量首次出现顺序”，不写在源码任何地方，顺序写反时报出与真实原因无关的类型错误，或者静默算错。

四条合起来是：为一个这个领域不需要的理论性质，付出了可判定性、可预测性与一个静默错误陷阱。所以语言里没有它。
