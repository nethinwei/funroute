# 能力边界

本文回答"FunRoute 最多能做到哪里"：每种数值能表示到哪里，每种运算在哪里停下，一个程序能多大、多深、多快，以及语言能表达什么、不能表达什么。每一条都是实测的，不是从常量抄来的。

- 测量于 2026-09-25，Apple M5，Go 1.26.3，darwin/arm64；基于提交 `4cdb5f7`，加上字节码验证器与语言服务位置换算的两处修复（见[已知的性能缺陷](#已知的性能缺陷)）。每一行都复测过一遍。性能数字取三次中最快的一次，换机器会变，量级不会。
- 取值范围的简表在 README [附录 B](../README.md#附录-b取值范围)；终止性与最坏成本的证明在 [termination.md](termination.md)；为什么是这些边界、否决过什么，见 [roadmap](roadmap.md) 的「关键设计决策」。

**一条总原则**：越过边界一律是错误，从不回绕、截断或悄悄舍入。能在编译期算出来的在编译期报；运行时的错误都有类别，宿主用 `errors.Is` 区分。

| 类别 | 何时出现 | `fallback` 接吗 |
|---|---|---|
| `ErrCompile` | 语法、类型、字面量越界、嵌套过深、指令过多 | —（编译期） |
| `ErrContract` | 入参不合契约（类型不对、整数带小数、未声明的币种同时是 `ErrCurrency`） | —（运行前） |
| `ErrArithmetic` | 溢出、除零、float 非有限、转换没有答案、数值参数超出取值范围 | 不接 |
| `ErrDomain` | 越界、缺键、空数组、长度对不上、重复键 | 不接 |
| `ErrCurrency` | 币种不一致或未声明 | 不接 |
| `ErrFuel` | fuel 用完，或栈深超出 `MaxStack` | 不接 |
| `ErrNoFxRate` | `using` 里没有这一对货币的汇率 | 接 |
| `ErrExtension` / `ErrDeadline` | 扩展函数失败、超时 | 接 |

## 数值的边界

### int

| 情形 | 结果 |
|---|---|
| 字面量 `9223372036854775807` | 通过 |
| 字面量 `9223372036854775808` | 编译错误：integer is outside int64 range |
| 字面量 `-9223372036854775808` | 通过：负号紧贴数字时读作一个负数，所以最小值写得出来 |
| `MaxInt64 + 1`、`MinInt64 - 1`、`2^62 * 2` | `ErrArithmetic`：integer overflow |
| `MinInt64 / -1`、`-MinInt64` | `ErrArithmetic`：没有这个 int |
| `MinInt64 % -1` | `0`（数学上成立，不报错） |
| `x / 0`、`x % 0` | `ErrArithmetic`：division by zero |
| `7 / -2`、`-7 % 2` | `-3`、`-1`：除法向零截断，余数随被除数 |
| 入参 `2^63`、`1.5`、`1e3` 给 int 参数 | `ErrContract`：不是 int（JSON 数字按原文读，不经过 float） |

### float

| 情形 | 结果 |
|---|---|
| `0.1 + 0.2` | `0.30000000000000004`；`==` 是精确比较，`0.1 + 0.2 == 0.3` 为 false |
| `1e308 * 10.0`、`1.0 / 0.0` | `ErrArithmetic`：非有限或除零。NaN 与 Infinity 进不来也出不去 |
| 字面量 `1e309` | 编译错误：超出 float64 |
| 字面量 `1e-400`、`0.1000000000000000055511151231257827` | 编译错误：写下的数不是一个 float64，并给出最近的那个 |
| 入参 `5e-324`（最小次正规数） | 通过 |
| int 与 float 混算：int 在 ±2^53 之内 | 通过（`9007199254740992 + 0.0`） |
| int 与 float 混算、`float(x)`：int 超出 ±2^53 | `ErrArithmetic`：不能精确表示为 float |
| `int(2.5)`、`int(9.3e18)`、`round(1e19)` | `ErrArithmetic`：会丢数据或超出 int |

### string

任意长度；下标、`len`、`slice` 都按码点计（`len("银行卡😀")` 是 4，`s[3]` 是 `"😀"`）。宿主传入的非法 UTF-8 字节原样保留，每个字节算一个码点；`upper`、`lower`、`slice`、`s[i]` 都不会把它改写成 U+FFFD。

### money

金额是 int64 个最小单位，所以能表示多少主单位取决于币种的小数位。币种的小数位由注册表声明，范围是 0–8；代码是大写字母开头的 3–8 位大写字母或数字。

| 币种（小数位） | 最大金额 |
|---|---|
| JPY（0） | `JPY 9223372036854775807` |
| USD（2） | `USD 92233720368547758.07`（约 9.2×10¹⁶ 美元） |
| KWD（3） | `KWD 9223372036854775.807` |
| BTC（8） | `BTC 92233720368.54775807`（约 922 亿） |

| 情形 | 结果 |
|---|---|
| `USD 92233720368547758.08` | 编译错误：amount overflows int64 |
| `USD 1.001`、`JPY 1.0` | 编译错误：小数位超过币种的位数（末尾的 0 也算） |
| 最大金额 `+ USD 0.01`、`* 2` | `ErrArithmetic` |
| `USD 1 + JPY 1` | 编译错误（`ErrCurrency`），闭合表达式在编译期就算了 |
| 入参 `"XYZ 1"` | `ErrCurrency` + `ErrContract`：未声明的币种 |
| 入参是 JSON 数字 `1.5` | `ErrContract`：金额只收 `"USD 1.70"` 或 `{"currency", "minor"}`，float 进不了金额 |
| `m / 3` | 编译错误：金额不能除以整数（会丢分），用 `allocate(m, 3)` |
| `m / USD 3.00` | `1/3`：同币种之比是精确的 ratio |

### ratio

约分后的 int64 分子/分母：只要约分后放得下就合法，MinInt64 的分子也算放得下。

| 情形 | 结果 |
|---|---|
| `ratio("0.000000000000000001")`（18 位小数） | 通过 |
| `ratio("0.0000000000000000001")`（19 位） | `ErrArithmetic`：至多 18 位小数 |
| `ratio("1/9223372036854775807")` | 通过 |
| `ratio("1/3000000000") * ratio("1/3000000007")` | `1/9000000021000000000`（分母 9.0×10¹⁸，恰好放得下） |
| `ratio("9223372036854775807") + ratio("1")` | `ErrArithmetic`：结果放不下 |
| 加减 | 中间积 128 位，只有约分后的结果放不下才报错（与 `math/big` 逐一对照过 2 万组） |
| 写法 | `2.9%`、`25bps`、`0.029`；入参可以是 `"0.5"`，也可以是 JSON 数字 `0.5`，数字按原文精确读入 |

### fxrate

正的、约分后的 int64 分子/分母。汇率文本的**有效数字总共约 18 位**：`150.123456789012345678` 放不下，是编译错误。汇率为零或负是 `ErrArithmetic`；同一币种之间恒为 1。

### 字面量

小数字面量的指数可以写到 ±2^30（超出是编译错误）；读作 float 时还要落在 float64 的范围里，读作比例或金额时还要放得进 int64。

## 运算的边界

### 金额运算

| 运算 | 能用到多大 |
|---|---|
| 带舍入方式的一步：`mul(m, 2.9%, @half_even)`、`convert(m, JPY, @half_even)`、`allocate` | 中间积 128 位，只要**结果**放得进 int64 就行：`mul(USD 92233720368547758.07, 2.9%, …)` 可以算；`convert` 按 150.25 换日元可以到 USD 6.1×10¹⁶ |
| `round(…)` 里的精确计算：`round(m * 2.9%, …)`、`round(m -> JPY, …)` | 精确金额也是 int64 分数。**保证可用**的上限是：最小单位数 ≤ MaxInt64 ÷ 约分后的分子。超过这个上限，只有约分后恰好放得下时才能算，放不下就是 `ErrArithmetic` |

`round` 里的保证上限，按 USD（两位小数）实测：

| 表达式 | 保证可用到 |
|---|---|
| `round(m * 2.9%, …)`（分子 29） | USD 3.18×10¹⁵ |
| `round(m -> JPY, …)`，汇率 150.25 JPY / USD（换算因子 601/400） | USD 1.53×10¹⁴ |
| `round(m -> EUR, …)`，汇率 0.92 EUR / USD（因子 23/25） | USD 4.0×10¹⁵ |

`round` 里不管有几步——乘比例、除比例、换汇、连写的多跳换汇——都只在最后舍入一次，因为比例、汇率和中间金额都是有理数：`using(150.5 JPY / USD, 0.5 EUR / JPY, round(USD 0.01 -> JPY -> EUR, @half_even))` 得 `EUR 0.75`（精确值 0.7525）。要让中间币种先落到最小单位，就逐跳写 `convert(…, @mode)`，同一笔得 `EUR 1.00`（中间先落到 JPY 2）。

要在接近 int64 上限的金额上换汇或乘费率，用带舍入方式的一步写法，不要写在 `round` 里。

### 函数的参数上限

| 函数 | 上限 | 超出 |
|---|---|---|
| `range` | 至多 10000 项；参数必须由输入规模界定：字面量、`len(…)` 或它们的算术组合，普通的 int 参数不行（编译错误） | `ErrArithmetic`（参数是常量时在编译期报，`range(len(xs))` 在运行时报） |
| `allocate(m, n)` | n 为 1–10000 | `ErrArithmetic` |
| `pad_left` / `pad_right` | 宽度 0–10000 | `ErrArithmetic` |
| `pow(int, int)` | 结果放进 int64（`pow(2, 62)` 可以，`pow(2, 63)` 不行）；按平方求幂，指数再大也只算几十步 | `ErrArithmetic` |
| `percentile` | 比例 0–1 | `ErrArithmetic` |
| `windows` / `chunk` | size ≥ 1 | `ErrArithmetic` |

这些上限保证扩展函数的计算量只随输入**规模**增长，不随参数的**数值**增长（见 termination.md 定理 B）。

## 程序的边界

| 边界 | 值 | 越过时 |
|---|---|---|
| 嵌套深度 | 1000 层，按语法树里的节点层数算：调用、运算符、容器、下标各算一层，括号不算。源码与 ExprJSON 用同一把尺子 | 编译错误 |
| 解析器递归 | 3000 层（只有多余的括号会碰到它） | 编译错误 |
| 指令数 | 10000（`CompileOptions.MaxInstructions`）。`len([a, …])` 写到 9998 项正好 10000 条，约 2000 项 `a * i + b` 也到了上限。指令数在编译完成后才检查，所以超出上限的大程序照样要付完整的编译代价 | 编译错误 |
| 运行时栈深 | 1024（`RunOptions.MaxStack`）。**数组字面量至多 1024 个元素**，常量组成的也一样：超过 256 个元素的常量数组不在编译期折叠 | 运行时 `ErrFuel`，而不是编译错误 |
| 默认 fuel | 10000（`RunOptions.Fuel` 不填时） | `ErrFuel` |
| 编译期折叠 | fuel 10000、栈 256；超出只是不折叠，留到运行时算 | — |
| 批处理 | 默认每批 64 条，或第一条到达 2 ms 后提交 | — |
| 语言服务 | 一次试运行至多 100 万 fuel、1 秒；stdio 一帧至多 16 MB、16 行头 | `ErrFuel`、`ErrDeadline`、断开 |

### fuel 能买多大的输入

fuel 的计费方式是：每条指令扣 1，每次函数调用再扣该函数声明的成本。实测：

| 程序 | 每个元素的 fuel | 默认 10000 fuel 最多处理 |
|---|---|---|
| `[x + 1 for x in xs]` | 7 | 约 1400 个元素 |
| `reduce(x in xs, acc = 0, acc + x)` | 7 | 约 1400 |
| `{string(x): x for x in xs}` | 7 | 约 1400 |
| `sum([x * 2 for x in xs if x > 3])` | 13 | 约 770 |
| `[x + y for x in xs for y in xs]` | 每对 7 | 约 37 × 37 |
| `sum(xs)`、`sort(xs)`、`xs[0] + xs[1]` | 0（整个调用 6–13） | 不受 fuel 限制 |

最后一行值得注意：std 的函数按固定成本计费，与数组长度无关。一次 `sort(xs)` 在 100 万个元素上也只扣 10 fuel，所以 **fuel 限制不住 std 函数的实际工作量**。这些函数的工作量由输入规模界定（多项式，见 termination.md），但不由 fuel 界定。需要硬性上限的宿主应当限制入参的规模，或者同时设 `ctx` 的截止时间。

### 大输入的吞吐

fuel 不设限，逆序的 int 数组：

| 程序 | n = 1 万 | n = 10 万 | n = 100 万 |
|---|---|---|---|
| `[x + 1 for x in xs]` | 1.3 ms | 6.6 ms | 56 ms（56 ns / 元素） |
| `sum([x * 2 for x in xs if x % 3 == 0])` | 1.2 ms | 12 ms | 121 ms |
| `{string(x): x for x in xs}` | 1.2 ms | 13 ms | 245 ms |

| `sum(xs)` | 10 µs | 70 µs | 0.72 ms（0.7 ns / 元素） |

### 编译

| 程序 | 有契约 | 无契约（全部推导） |
|---|---|---|
| 基准规则（`BenchmarkCompile`） | 42 µs | — |
| 100 项 `[a * i + b, …]`（1.2 KB） | 1.1 ms | 2.9 ms |
| 500 项（6.4 KB） | 5.7 ms | 37 ms |
| 1000 项（13 KB） | 12 ms | 135 ms |
| 1900 项（25 KB） | 23 ms | 484 ms |
| 无契约的加法链 10 / 100 / 1000 项（`BenchmarkInferChain`，变量互不相同） | — | 0.09 / 0.89 / 10.5 ms |

有契约时编译随程序长度线性增长。无契约时，如果很多重载调用共用同一批参数（上表的 `a`、`b`），推导会接近平方增长；变量互不相同时仍是线性的。生产环境的规则都带契约，这个差别主要体现在工作台和语言服务上。

### 已知的性能缺陷

1. **字节码验证器的内存曾是 O(指令数 × 栈深)**（已修复）：它原来在每条指令上保存一份完整的栈类型快照；编译器折叠常量时也要跑验证器，所以大的数组字面量在编译期就会触发。现在只在跳转目标处保存状态，直线代码沿用同一个状态往下走，`TestLoadingStraightCodeKeepsOneState` 守着。`sum([常量, …])` 的编译：

   | 元素个数 | 修复前 | 修复后 |
   |---|---|---|
   | 2000 | 47 ms / 342 MB | 7 ms / 19 MB |
   | 8000 | 0.43–0.53 s / 5.1 GB | 25 ms / 84 MB |
   | 10 万（约 69 万字节的源码） | 进程被系统杀掉 | 0.26 s / 1.06 GB，然后因指令数超过 10000 而被拒 |

   修复后的内存随元素个数线性增长，每个元素约 10 KB，大部分花在折叠时逐个解码常量上。
2. **语言服务在很长的一行上曾按平方增长**（已修复）：每次把字节偏移换成行列，原来都要从行首数一遍 UTF-16 单位，语义标记和语法树要为每个 token 或节点换算一次。现在每行只记下 UTF-16 长度与 UTF-8 长度不同的字符，连同到每个字符为止少了多少个单位的前缀和，换算用二分查找，是 O(log)；纯 ASCII 的行什么都不记。这是 rust-analyzer 的 `line-index` 的做法，再加上前缀和，一行塞满中文时也不退化。`TestPositionsAreTheWalkFromTheLinesStart` 对照旧算法逐个偏移校验，`BenchmarkPositionsOnALongLine` 守着线性：

   | 8000 个数写在一行 | 修复前（语义标记 / 语法树） | 修复后 |
   |---|---|---|
   | 纯 ASCII（47 KB） | 391 ms / 182 ms | 3.5 ms / 5.5 ms |
   | 含中文字符串（87 KB） | 777 ms / 381 ms | 4.0 ms / 5.3 ms |
3. **格式化耗时随嵌套深度按平方增长**：1000 项的减法链要 0.17 秒。深度上限是 1000，所以单条链有界；但很多条长链并列时，总耗时会随之上升。
4. **无契约时推导可能接近平方增长**：见上文的编译表。

## 表达能力的边界

### 能表达的

- **一个程序就是一个表达式**：参数、类型和返回类型由宿主的契约给出，程序文本里不声明。
- **8 个形式**：`let`、`switch`（值匹配与条件链，枚举穷尽检查）、列表与字典推导（可以连写多个 `for`，带 `if` 筛选）、`reduce`、`using`（换汇作用域）、`&&` / `||` / `!`（短路）；此外还有惰性的 `if` 与 `fallback`，以及记录更新 `r with {a: 1}` 和换汇 `amount -> JPY`。
- **函数**：内核 19 个名字、63 个重载，是算术、比较、转换、`len`、`in`、下标、`if`、`fallback`；std 加上金额能力再多 68 个名字（涵盖聚合、排序与选择、分组、字典、字符串、数值、金额），并给内核的名字补上金额的重载，重载总数到 230。宿主可以注册任意多个自己的函数（模型、查表、远程调用），它们与内置函数同等参与类型检查、补全和批处理。
- **类型**：`bool`、`int`、`float`、`string`、`array<T>`、`dict<T>`、`record{…}`、名义枚举、不透明句柄 `handle<name>`、`money`、`ratio`、`fxrate`、`currency`。record 可以直接写字面量（`{a: 1, b: "x"}`）；枚举由契约或注册表声明（舍入方式 `@half_even` 就是注册表的）；类型别名只在契约里。
- **成本是静态可估的**：每个程序都终止；只要扩展函数的代价是多项式，最坏成本就是输入规模的多项式，次数不超过循环嵌套深度加一（termination.md 定理 A、B）。

### 不能表达的，以及怎么绕

| 不能 | 为什么 | 需要时这样写 |
|---|---|---|
| 递归、`while`、无界循环 | 必然终止与多项式成本上界会失效 | 推导式或 `reduce` 遍历有限的输入 |
| lambda、把函数当值传递 | 同上：函数值能构造出递归 | `sort_by(候选, 键数组)`、`top_k(候选, 键数组, k)`：先用推导式算出键，再按键选择 |
| 在程序里定义函数或类型 | 契约归宿主；规则只是表达式 | 类型写在契约里，公共逻辑注册成宿主函数 |
| 变量赋值与状态 | 纯表达式；同一输入永远得到同一答案 | `let` 绑定新名字；记录用 `with` 得到新值 |
| `null`、`??`、`?.` | null 会静默传播 | `get(d, "k", 默认值)`、`"k" in d`、`len(xs) > 0` |
| 时间、随机数、I/O、正则 | 不纯，或成本无法静态估计 | 由宿主注册函数，时间与时区作为参数传入 |
| 字典的键不是字符串 | 键是 JSON 对象的键 | 把键转成字符串：`{string(x): … for x in xs}` |
| 超过约 1024 个元素的数组字面量 | 运行时栈深 1024 | 作为参数传入，或调大 `MaxStack` |
| 金额除以整数 | 会丢分 | `allocate(m, n)`，一分不丢 |
| 精确金额离开 `round` | `round` 外的金额都是整数个最小单位 | 在 `round(…, @mode)` 里算完，或者用带舍入方式的一步写法 |
| 换汇写在 `using` 外，或自动经过第三种货币 | 用哪条汇率必须从 `using` 看得出来 | 连写每一跳：`using(报价…, round(amount -> JPY -> EUR, @mode))`，在 `round` 里整段精确，只在最后舍入一次；要让中间币种落到最小单位，写 `convert(convert(amount, JPY, @mode), EUR, @mode)` |
| 连着写比较 `a < b < c` | 语言不给它含义 | `a < b && b < c` |
| 张量、float32、bytes、位运算、JSON 编解码、base64 | 归宿主或引擎 | 句柄穿过规则，由宿主函数处理 |
| `zip`、左连接、排列组合 | 配对要有字段名；左连接需要"空"；组合的结果规模是阶乘级 | `[{a: xs[i], b: ys[i]} for i in indices(xs)]` |

另外两处语法约定：`%` 紧贴数字时是比例（`2.9%`），取模要在两边留空格（`10 % 3`）。`fallback` 只接"数据暂时不可得"，接不住规则或数据自身的错误。

- 基准：`go test ./internal/machine ./internal/compile -run XXX -bench . -benchtime 1s`。
- 其余数字来自一次性的探针测试：用公开 API 编译并运行上文的每个表达式，用二分查找找出恰好够用的 fuel 与金额上限，再对大输入与语言服务计时。探针测完就删掉了，不在仓库里；要复现，按上文各表里的表达式和入参逐条跑即可。
