# 语义宪章

"纯""强类型""必然终止""冻结""相等"这几个词，语言、编译器、运行时与宿主各有一层。本文把每个词的定义写在一处；其余文档用到它们时以这里为准，不再各自加例外。取舍与否决过的方案见 [roadmap.md](roadmap.md) 的「关键设计决策」。

| 条 | 主题 | 一句话 |
|---|---|---|
| S1 | 金额的代数 | 只有不带币种的零是多态的；相等只在能相遇的值之间有定义，所有相等运算用同一个关系 |
| S2 | 确定性 | 分三层：语言核心、同一环境、宿主效果 |
| S3 | 成本模型 | 步数是输入规模的多项式，次数 ≤ 循环嵌套深度 + 用到的函数的代价次数 |
| S4 | 求值策略 | 分支惰性、`let` 严格；`any`/`all`/`first` 套推导式是短路形式 |
| S5 | 批处理契约 | 合批只改调用次数；共享的调用用第一条请求的 ctx 值、最晚的截止时间，互不连累 |
| S6 | Artifact 的身份 | 冻结签名绑定与币种表的 stamp，不冻结函数的行为 |
| S7 | 三种表示等价 | 源码、ExprJSON 与字节码互相等价；ExprJSON 能导入当且仅当有源码打印得出它 |

## S1 金额的代数

```text
money = amount(currency, minor) | zero
```

- 只有**不带币种的零**（`0`、`sum([])`、Go 的 `funroute.Money{}`、JSON 的 `0`）是多态的，它与任何币种相遇。`USD 0` 与 `EUR 0` 是两个币种各自的零，不是同一个值。
- **两个值能相遇**：两个金额里至少一个不带币种，或币种相同；两个汇率是同一货币对。相遇之后，金额按最小单位比较，汇率按比值比较。
- **相等只在能相遇的值之间有定义**：`USD 0 == EUR 0`、`USD 1 == EUR 1` 都是 `ErrCurrency`，不是 `false`（两边都闭合时在编译期报出）。`0 == USD 0`、`0 == EUR 0` 都是 `true`。
- **凡是做相等判断的运算都用这同一个关系**：`==`、`!=`、`in`、`switch` 的值匹配、`index_of`、`unique`、`intersect`、`except`。容器里的金额也一样，按**类型里的位置**检查：一条字段路径是一个位置，一个数组的所有元素、一个字典的所有值各算同一个位置；同一位置上出现两种币种就是 `ErrCurrency`。所以判定与元素的顺序无关：`USD 1 in [EUR 1, USD 1]` 是 `ErrCurrency`，不会因为先碰到 `EUR 1` 或先碰到 `USD 1` 而得出不同答案。
- 排序与按键选择（`sort_by`、`top_k`、`min`、`max` 等）对同一个位置的要求相同：同一数组里的金额必须同币种，不带币种的零取那个币种的零。
- **相等不是全序关系，"能相遇"也不传递**：`USD 0` 与 `0` 相遇、`0` 与 `EUR 0` 相遇，`USD 0` 与 `EUR 0` 却不相遇。这是不带币种的零换来的代价：空集合的和、兜底的零不需要知道币种。

因此首页说的"强类型"准确地说是：**结构强类型；币种是值，在运算处检查**。类型系统约束的是形状（`money` 与 `int`、record 的字段），不约束币种；`money<USD>` 这类带币种的类型已经否决过。

## S2 确定性

同一条规则在什么条件下给出同一个答案，分三层：

1. **语言核心**：给定参数的值，答案确定。包括 float：先乘后加一律先舍入乘积，arm64 与 amd64 得同一个数。
2. **同一环境**：读宿主机器状态的函数只在同一环境下确定。目前有两类：日历函数（`hour`、`weekday`、`day`、`month`、`start_of_day`、`add_days`）读宿主的 tzdata；指数不是整数的 `pow` 是 Go 的 `math.Pow`，末位随 CPU 是否有 FMA 而变。两类都标了 `varies`，不在编译期折叠，所以 Artifact 与编译它的机器无关。
3. **宿主效果**：扩展函数、`ctx`、`Doc.Detached`，以及 `fallback` 接住 `ErrDeadline`。`fallback` 把超时当作数据暂不可得，这让答案依赖时效：同一输入，引擎快时走第一候选、慢时走兜底。这是有意的取舍，不是缺陷。

"同一输入永远同一答案"指前两层：**同一输入、同一环境**。

## S3 成本模型

定理 B（[termination.md](termination.md#3-定理-b多项式时间上界)）的准确说法是：忽略对数因子，求值步数是输入规模 n 的多项式，**次数可以从语法数出来**——循环把源与循环体的次数相加，调用把实参的次数乘以函数的代价次数 d_f。只看循环嵌套深度不够：`let` 把一个大容器带进另一个循环时次数会相加。内核与标准库的函数各自的代价见 termination.md 的[代价表](termination.md#代价表)：多数是 O(n)（d_f = 1），排序类是 O(n log n)，`unique`/`intersect`/`except` 在元素没有键时退化为 O(n·m)（d_f = 2）。

"最坏成本可由输入规模静态估出"只对语言部分成立；扩展函数的代价是宿主的承诺。

## S4 求值策略

| 形式 | 策略 |
|---|---|
| `if`、`switch`、`fallback` | 运行时只走选中的分支 |
| 闭合表达式的失败 | 无论写在哪个分支，都是编译期的**静态检查**，不是运行：`if(true, 1, 1 / 0)` 是编译错误 |
| `any`、`all`、`first` 直接作用于推导式 | **短路形式**：答案定下之后的项既不计算，也不失败。这是语义，不是优化 |
| `sum`、`len` 等套推导式的融合 | 只改执行方式，答案与失败都不变 |
| `let` | 严格求值：绑定的值在主体之前算出 |

所以对短路形式而言，`let(big = [10 / x > 2 for x in xs], any(big))` 与 `any([10 / x > 2 for x in xs])` 不等价：`xs` 是 `[1, 0]` 时，前者先建出整个数组，在 `x = 0` 处除零失败；后者在第一个元素处得到 `true` 就停下。

宿主给函数声明 `Fold.Stops` 或 `Fold.First`，就是声明它是短路形式。`Fold` 记在签名清单（`Manifest`）里，按清单编译与按真实注册表编译得出同一个 Artifact；目录显示 `short_circuit`，审查规则时看得见。

## S5 批处理契约

`Batch`、`program.Batch` 与 `RunBatch` 把可合批的扩展函数调用合成一次引擎调用。合批**只改变调用次数**；在下面的前提下，每条请求得到与单独 `Run` 相同的答案：

- 扩展函数是纯的，并且只依赖第一条请求的 ctx 里的值；
- 一次引擎调用的失败由同批共享：它失败，同批每条请求都在这一步失败。

共享的那次调用的 ctx：

- **值**取批内第一条请求的 ctx（trace 等到得了引擎）；
- **截止时间**取批内最晚的那个；有请求没设截止时间，就不设；
- **取消**只在批内所有请求都不再等待时发生：一条请求取消不连累同批的其他请求。

每条请求只等到它自己的 ctx 结束：

- 请求还没被执行器取走时，`Run` 因 ctx 提前返回，这条请求被标为放弃，执行器永远不读它；
- 已经被取走的，`Run` 等到它自己那一次运行结束再返回。

所以 `Run` 返回之后，宿主总能安全地复用 `args` 与 `In` 指向的内存，参数也不需要拷贝（`[]float64` 特征向量照旧零拷贝）。代价是 ctx 结束之后，最多再等到已经开始的那一步结束。唯一不等的是 `Doc.Detached` 的函数：超时后它被丢在后台继续跑，所以交给它的实参连同容器先整份复制一次，它读的始终是自己的那份。

## S6 Artifact 的身份

Artifact 冻结的是**签名绑定**与**币种表的 stamp**：用到的每个函数的完整签名、编译依据的 `Fold`，以及字节码里写死的币种与小数位。签名或币种表变了，旧 Artifact 拒绝装载。

它**不冻结行为**：同名同签名的函数换了实现、`Doc.Timeout`/`Detached` 这类运行时策略、宿主的 tzdata，都由宿主负责。没有可靠的方法给 Go 实现取指纹，tzdata 已归入 S2 的环境层，所以不设行为 stamp。

一条规则的意义是 **(源码, 契约, 注册表清单)** 三者的组合。

## S7 三种表示等价

源码、ExprJSON 与字节码是同一个程序的三种表示：

- 源码经 `Parse` 得 ExprJSON，ExprJSON 经 `Format` 得源码，两者往返得同一个 ExprJSON（`FuzzFormatRoundTrip`）；
- **ExprJSON 能导入，当且仅当有源码打印得出它**：导入时每个节点的 `check` 拒绝源码写不出的形状（如带 `flatten` 却不是嵌套 `for` 的推导式），`FuzzImportExprJSON` 对导入成功的每个 ExprJSON 做 Format → Parse 往返；
- 字节码由 ExprJSON 编译得出，装载时由验证器再证明一次类型与终止性，不重新解析 ExprJSON。验证器保证的是**安全**：一份不是编译器写出的字节码（存储里被改写、手写的）装载后不会打崩宿主、不会无视 `ctx` 不返回、类型都对；它不重做编译器的其他证明——精确金额只在 `round` 里（S1）由编译器保证，伪造的字节码可以算出错的金额，就像它可以写出错的算式。

## 术语表

| 说法 | 准确含义 |
|---|---|
| 强类型 | 结构强类型；币种是值，在运算处检查（S1） |
| 纯 | 语言里没有副作用；扩展函数的纯度是**宿主的承诺**，VM 只兜住 panic。`Constexpr`、`Fold`、合批都要宿主显式声明才启用，所以没有另设 Effectful 标记 |
| 必然终止 | 前提是扩展函数终止且不重入 `Run`；`Detached` 留在后台的工作不算在规则里 |
| 同一答案 | 同一输入、同一环境（S2） |
| 没有默认舍入 | 指落在两个最小单位之间的运算（乘除比例、换汇、`prorate`）。`allocate` 一分不丢，余数怎么分有缺省策略，那不是舍入 |
| `round` | 两个重载，同名不同义：`round(float)` 取整得 `int`；`round(money 表达式, @mode)` 是精确计算的范围加一次舍入 |
| 隐式转换 | 字符串与数值之间没有。int 与 float 混算经由 16 个混合重载，±2^53 以内精确，超出在运行时拒绝 |
| 币种作键 | 币种可以作字典的键：`rates[currency(m)]`，也可以在 `switch` 里匹配 |
| `->` | 词法作用域里的 `convert`：报价来自包住它的最内层 `using` |
| 冻结 | 签名绑定与币种表的 stamp，不是行为（S6） |
| 只读 | 零拷贝的读取（`Any`、`FromValue`、`Array`）交出的是 backing，从那一刻起双方都只读；这是边界契约。内省（`Overloads`、`Resolve`）返回快照，改它不影响注册表 |
