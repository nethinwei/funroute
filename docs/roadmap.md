# 路线图与设计决策

本文回答三个问题：FunRoute 现在能做什么、关键设计为什么是现在这样、接下来做什么。只记录**当前成立**的决策；被推翻的旧方案只在相关决策的"否决了什么"里用一句话交代。

## 原则与定位

**性能让位于适用性，正确性不让位于任何东西。** 所有取舍都从这一条推出。

相对于通用表达式求值器（如 `expr`），FunRoute 的价值不在求值本身，而在它周围的治理层：

- 规则是带 digest、冻结了 ABI 的 Artifact；
- 能力边界由注册表定义，默认关闭；
- 契约归宿主，并参与类型推导；
- 成本有界，程序必然终止；
- 文本与结构视图无损互转；
- 模型接入是一等公民。

每一项改进都应落在这几条之内。

## 已完成的能力

**语言**

- 纯表达式：`if`、`switch`（值匹配与条件链，枚举穷尽检查）、`let`、`fallback`、列表与字典推导（可连写多个 `for`）、`reduce`。
- 类型：`bool`、`int`、`float`、`string`、`array`、`dict`、`record`（字段顺序即类型，字段更新写作 `r with {a: 1}`）、nominal 枚举、不透明句柄 `handle<name>`。
- 金额：`money`、`ratio`、`fxrate`、`currency`，显式舍入、`round` 内精确计算、`using` 里换汇（见下文「金额」）。
- 索引、`%`、`in`、`len`；字符串是完整容器（`s[i]`、`"b" in text`，按码点）。
- 编译期求值：不读参数且每个调用都获授权的子表达式在编译期算完；闭合表达式的失败是编译错误。
- 错误带位置（字节区间），宿主用 `funroute.LineColumn` 换算成行列。

**SDK**

- 零拷贝值层：原生 Go 切片与映射作 backing，边界不转换。
- 类型化绑定 `funroute.Bind[In, Out]`：契约就是两个 Go 类型，`Program.Run` 从 struct 直接读参数。
- 注册：只有 `Registry.Register(FunctionSpec)`；`Go`/`GoBatch` 按 Go 签名反射注册单条与批量实现，或手写 `Params`/`Result`/`Eval`。
- 预算：`ctx` 贯通、函数级 `Doc.Timeout`、无法取消的引擎用 `Doc.Detached`、fuel 成本上限。
- 类型化错误：`ErrCompile`、`ErrContract`、`ErrFuel`、`ErrDeadline`、`ErrExtension`、`ErrCurrency`、`ErrArithmetic`、`ErrDomain`、`ErrNoFxRate`，一律 `errors.Is`。
- 批处理第一级：字节码证明可以提前算的模型调用按批合并，惰性 `if` 不受影响。
- 标准库 `extensions/std`：聚合、序列、选择与分组、字典、字符串、数值，全部可在编译期折叠；每个函数带可运行的案例。

**工具**

- 语言服务 `lsp`：语义标记、诊断、补全、悬停、签名提示、格式化；stdio 与 WebAssembly 两种传输。
- 签名清单：没有实现的宿主函数只登记签名，语言服务照常检查。
- 策略工作台：编辑器加结构视图，纯静态页面，发布到 GitHub Pages。
- 格式化器与 ExprJSON 的往返由模糊测试守着。

## 关键设计决策

### 语言形态

| 决定 | 为什么 | 否决了什么 |
|---|---|---|
| 规则只是表达式；参数、类型、返回类型由宿主在编译时传入 | 控制台本来就存规则元数据（版本、灰度、审批），参数类型是同类信息；写进语言就有两份元数据 | 在规则文本里声明参数 |
| 语言不图灵完备：只遍历有限输入，没有递归与无界循环 | 每个程序都终止，最坏延迟有多项式上界（见 `docs/termination.md`） | lambda、递归、`while` |
| 聚合不进内核：`sum`/`min`/`max` 等是 `extensions/std` 的普通函数，`reduce` 留给自定义折叠 | 内核保持 19 个函数名；日常写法是"推导式 + 聚合函数" | 为每种聚合加语法 |
| 能凭空造数组的函数（`range`、`allocate(m, n)`）的整数实参必须由输入规模界定：字面量、`len(容器)` 或它们的算术组合 | 否则一个整数参数就能让规则跑任意久，多项式上界失效 | 要求实参是常量（会误伤 `range(len(fees))`） |
| 没有 null：越界、缺键、除零都是错误（`ErrDomain`、`ErrArithmetic`，`fallback` 不接）；兜底写 `get(d, k, 默认值)` 或先判断 | null 会静默传播 | `nil`、`??`、`?.`、Option |
| 编译期求值由 `Doc.Constexpr` 授权：内核与 std 有，模型、时钟、远程调用没有 | 否则编译规则时会调用推理引擎，同一条规则不同时间编译出不同结果 | 显式的编译期关键字（如 `const`、`comptime`） |
| 运算符与推导式都是 parser 里的糖，不新增节点；格式化结果必须解析回同一个程序 | 语法节点只有一份定义，ExprJSON 与 digest 稳定 | 为运算符加节点 |
| `%` 紧贴数字一律是比例（`2.9%`）；取模要留空格（`10 % 3`） | 同一个 `%` 不靠后文或空白改变意思 | 按后文猜是比例还是取模 |
| 推导只读一遍程序：每个节点一个类型项，多个重载都合适的调用是一个"选择"；先传播必然的约束（候选不再合适就去掉，只剩一个就定下），再由内向外逐个决定剩下的选择，取代价最低的候选（不留未定类型、不改字面量的种类、不提升、类型最朴素），每次决定后再传播；决定导致矛盾的候选被去掉；最低代价并列就报歧义并列出候选 | 推导耗时随程序长度近线性（无契约的 `x0+…+x1000` 约 60 ms）；变化都记在可撤销的 trail 上，试一个候选只付它改动的代价 | 为每种重载组合克隆一份推导状态再打分（无契约的 20 项加法就要 20 秒以上） |
| 变量之间保留 int→float 隐式提升，由 16 个混合重载 `(int, float)`/`(float, int)` 表达，只在没有同型解读时才用 | 提升规则就是注册表里的签名，推导不需要子类型；超出 2^53 的整数在运行时拒绝，不丢精度 | 只让字面量自适应、变量不提升（Go 式） |
| 重载不按"只差一个类型参数"合成受约束的类型变量 | 每个重载背后本来就是不同的 Go 实现（`eachType` 已是一处可读的清单）；新的推导对重载集合已是线性，合并换不来复杂度 | 签名里的 `T ∈ {int, float, …}` 及一个求值函数按种类分派 |

### 金额

金额与普通计算**按类型区分，逐个运算判定，没有模式**。一个运算的操作数里有 `money`，它就按金额规则执行；否则一切照旧。

| 决定 | 为什么 | 否决了什么 |
|---|---|---|
| `money`、`ratio`、`fxrate`、`currency` 都是不带参数的普通类型；币种是值的属性，与 Go 的 `Money{currency, minor}` 一致 | 编译期能证明的币种只有字面量；契约与运算产生的币种本来就要运行时比对 | 类型上带币种单位（`money<USD>`、`money<?>`、币种变量）及整套单位推导 |
| 币种在运算处检查（加减、比较、`==`、`in`、相除、换汇、std 聚合），不一致是 `ErrCurrency`；闭合表达式经常量折叠在编译期报错 | 检查点就是两笔钱相遇的地方，宿主与规则得到同一个答案 | 用契约约束币种 |
| 金额是 int64 个最小单位；币种与小数位由注册表声明（0–8 位），`std.ISO4217()` 给出默认表 | 精确、零分配；渠道的小数位常与 ISO 不一致，由宿主说了算 | 通用 decimal 类型 |
| 比例、汇率与 `round` 里的精确金额都是约分后的 int64 分子/分母，中间积 128 位；放不下是 `ErrArithmetic`，从不悄悄舍入 | 保证零拷贝、零分配；约 18 位数字的精度够支付场景的报价与费率 | 1e-10 定点比例（丢位、比例间运算要舍入）；`math/big` 汇率（每次换汇都分配） |
| 不带币种的零（`0`、`sum([])`、`funroute.Money{}`）与任何币种相加、比较都成立 | 空集合的和、兜底的零不需要知道币种 | 要求每个零都带币种 |
| 比例只为金额服务：没有 int 或 float 与比例的混合运算，也没有互转；从文本读用 `ratio("0.029")` | `n * fee` 这类量纲不明的式子不该编译；float 是把近似值带进精确计算的入口 | int 隐式加宽为比例、`ratio(float)` |
| 金额类永不经过 float：小数字面量就是它写下的十进制数（`money.Decimal`），读作比例时按数字精确得到，读作 float 时必须恰是那个 float64，否则在字面量处报编译错误；宿主输入的 float64 进不了 `money`/`ratio`/`fxrate`，只收字符串、`json.Number` 与整数 | JSON 解码成 `any` 时 float64 已经被舍入过一次；比例字面量不再受 float64 的 17 位有效数字限制 | 小数字面量先读成 float64 再转成比例；按最短文本把 float64 输入读成比例 |
| 金额相除只有一种意思：同币种之比，得 `ratio`；成交汇率用 `implied(到账额, 支付额)` | 同一段文字不该按上下文变成两种运算 | `money / money` 按期望类型读成比例或汇率 |
| 汇率的运算只有加点（`fxrate × ratio`）与同一货币对的比较；换汇只有 `->` | 每一种汇率运算都是一处可能把汇率用在错误币种上的地方；加点精确、换汇时只舍入一次 | 汇率相乘、交叉、倒数、平均；把换汇写成乘法 |
| 同一币种之间的汇率恒为 1 | 规则不必先判断支付币种是否等于结算币种 | — |
| `allocate` 一分不丢：各份向零取整，余数缺省按最大余数法发放，末尾可写策略（`@all_last` 等） | 清分里常见"舍入差全给某一方"的约定 | 余数只按权重给（小份额方系统性少分） |
| 加密货币按业务精度声明（稳定币 6 位、其余 8 位），链上精确金额由宿主换算 | int64 按 wei 计只放得下约 9.2 ETH；128 位金额会让所有程序变慢 | 128 位金额 |

### 舍入

| 决定 | 为什么 | 否决了什么 |
|---|---|---|
| 舍入永远写出来：会落到两个最小单位之间的运算（金额乘除比例、换汇、`prorate`）要么写在 `round(表达式, @mode)` 里，要么末尾带舍入方式当场舍入 | 读规则的人一眼看到舍入点与方式；Go 侧的 `MulRatio`、`Convert` 本来就要求传舍入方式 | 注册表级的默认舍入方式 |
| `round` 里精确计算，只在末尾舍入一次；精确值不出 `round`（进容器、记录、宿主函数或作结果都是编译错误） | `amount * 2.9% * 50%` 只舍入一次；`round` 外的金额永远是整数最小单位，宿主、JSON 与 std 都不必认识精确金额 | 每一步都舍入（曾经的做法，`a * r1 * r2` 与 `a * (r1 * r2)` 可能差一分） |
| 舍入方式有七种（`half_even`、`half_up`、`half_down`、`down`、`up`、`ceiling`、`floor`），是注册表提供的枚举 `rounding` | 业界的默认值互相矛盾（欧盟 1103/97 半数远离零，IEEE 754 十进制与 .NET 是银行家），只能由规则写明 | 语言内置某一种默认 |
| 精确金额不是一种类型：推导选定重载之后，一遍数据流检查（`compile/exact.go`）证明精确值只流向接受它的地方 | 整额金额是精确金额的特例，做成类型就要子类型与上下界求解（`if(c, 精确, 整额)` 的合流），推导会比它守护的规则复杂得多 | `exact<money>` 类型 |

### 换汇

| 决定 | 为什么 | 否决了什么 |
|---|---|---|
| 汇率就是参数：宿主把报价作为 `fxrate` 或 `array<fxrate>` 参数传入（Go 传 `[]FxRate`，零拷贝） | 报价从哪来、何时过期是宿主的事；规则只看得见传给它的汇率 | 运行时统一汇率表 `RunOptions.Rates`、按名字传入的具名汇率表、报价元数据 |
| `->` 只能写在 `using(报价…, 主体)` 里，写在外面是编译错误 | 规则用哪条汇率，看 `using` 就知道 | `->` 写在哪里都能换汇 |
| `using` 永远隔离：外层的报价不参与；要沿用外层就写 `fx(base, quote)` 读出来 | 没有"补充"与"覆盖"两种组合要记 | `using` 里用 `...` 引入外层 |
| 换汇单跳：只用这一对货币的报价或反向报价的倒数；要经过别的货币就连写 `amount -> USD -> EUR`。在 `round` 里整段精确，只在最后舍入一次；要让中间币种落到最小单位，就逐跳写 `convert(…, @mode)` | 用哪条汇率不取决于报价里还有什么；比例与汇率是有理数，多跳换汇与多步乘比例一样只在最后舍入，与 `FxRate.Chain` 的交叉汇率换一次得同一个数 | 自动搜索最短路径；连写的 `->` 每一跳隐式各舍入一次（舍入点从源码看不出来） |
| 找不到汇率是 `ErrNoFxRate`，`fallback` 接它 | 与扩展函数失败同类：数据暂时不可得，不是规则写错了 | — |

### 公开接口

| 决定 | 为什么 | 否决了什么 |
|---|---|---|
| `funroute` 是唯一的公开包（`import "github.com/nethinwei/funroute"`，根目录只有 `funroute.go` 一个文件），只有类型别名、构造函数、访问方法与选项结构体 | 宿主造不出违反不变量的值（币种一定已声明、汇率一定为正） | 字段可写的数据类型（如 `Money{Currency, Minor}`） |
| AST 不公开，程序一律用 ExprJSON 交换 | 语法节点可以改而不破坏宿主 | 导出 AST |
| Artifact 冻结签名与成本，digest 覆盖 ExprJSON；签名或成本变了，旧 Artifact 拒绝装载 | 运行环境里的函数变了不会悄悄改变规则的含义 | 装载时重新解析、重新推导 |
| 用到金额的 Artifact 带金额戳：字节码里写死的币种及其小数位 | 小数位变了必须拒绝装载；新增币种不该让已部署的 Artifact 失效 | 整张币种表的哈希 |
| 金额运算只写一份：在 `internal/money` 里，是 `Money`/`Ratio`/`FxRate`/`ExactMoney` 的 Go 方法；内核只调用它们 | 宿主在规则旁边算出的数与规则逐分相同 | 语言与 Go 各一份实现 |
| 注册只有 `Registry.Register(FunctionSpec)` 一个入口；`Go`/`GoBatch` 字段按 Go 签名读出参数与结果（返回 `R` 或 `(R, error)`）：常见签名（标量与 int/float 向量进、标量出，可带 `error`，向量也可带 `context.Context`）直接调用，约 25 ns、0 次分配，与反射调用逐项对照（`TestDirectCallsAnswerAsReflection`）；其余签名走 `reflect.Call`，约 300 ns。要零开销也可手写 `Params`/`Result`/`Eval`，两者二选一 | 任意元数与嵌套，签名从 Go 类型读出；一个入口，不必在三个函数间选 | 按元数展开的 `Fn1/Fn2/…` 泛型；`Logic`/`Model` 两个以 registry 为首参、`fn, batch any` 的包级函数 |
| 一个错误 = 类别 + 原因：分类层自己就是 `ErrExtension`/`ErrDeadline`/`ErrContract`，`Unwrap` 通向原因（`money.Classify`）；已带任何类别的错误原样传递 | `errors.Is` 答类别，宿主仍认得出自己的错误与 `context.DeadlineExceeded`，文案不变 | `%w: %v`（原因只剩文字，身份丢失）；`%w: %w`（一个错误并列两个错误） |
| 超时默认信任 `ctx`；无法取消的引擎注册时标 `Detached`，VM 在独立 goroutine 里等，到点放弃 | 大多数引擎能响应取消；`Detached` 每次约 1 µs，只给不能取消的用 | 所有调用都起 goroutine |
| `fallback` 只接扩展函数失败、超时与 `ErrNoFxRate`；不接 fuel 耗尽、类型错误、`ErrArithmetic`、`ErrDomain`、`ErrCurrency` | 规则不能吞掉自身或数据的错误 | 什么都接 |
| 装载时对字节码做一遍带类型的抽象解释（`machine/verify.go`）：每条路径上栈与局部槽的类型、每条指令的输入输出、调用按签名实例化、合流处栈一致；同时得出栈的深度与每条指令入口的栈深，寄存器形式按它布局。执行时只检查宿主函数的回答 | 编译器证明过的，对来自任何地方的 Artifact 再证明一次，执行循环因此快约 15%；栈深只有一个来源 | 执行时逐元素检查类型（旧做法）；Artifact 自带 `max_stack` |
| 常量是"静态类型 + 值的 JSON"，读回走与宿主入参相同的 `coerce` | 常量没有自己的编码；`@member` 以枚举类型存入，读回时校验成员 | 按值的种类手写的常量结构体 |
| 错误类别只有一张表（`machine/errors.go` 的 `errorClasses`），一个错误由它最具体的类别命名，并决定 `fallback` 接不接 | 机器、`fallback` 与语言服务读同一张表，README 的表由测试对照 | 各处各写一份类别清单 |
| 测试分两处：`foo_test.go` 跟着 `foo.go` 测一个文件的代码；不属于任何一个文件的放在 `tests/`（公开面按主题的 `api`、示例流水线 `conformance`、文档里的边界 `limits`、性能报告 `perf`），只用公开包。根目录仍只有 `funroute.go` 一个 Go 文件 | 公开面是一个转发文件，它的测试没有源文件可对；按文件组织会把"整个系统的性质"拆散 | 根目录放 `funroute_test` 包（与根目录只有一个 Go 文件的规则冲突）；测试套件放在 `internal/` 下 |
| 文档里的边界由测试生成：`docs/limits.md` 的说明手写，表格在 `<!-- limits:名字 -->` 区块里，由 `tests/limits` 经公开包实际运行填入，`go test` 逐字比对；性能数字由 `tests/perf` 生成进 `docs/perf.md`，按需提交，不做断言 | 手写的数字会与实现悄悄脱节（连写换汇的舍入就是这样被发现的）；耗时随机器变化，不能断言 | 整篇文档生成（说明写不进去）；把耗时写成断言（换台机器就失败） |
| `examples/` 只放 Go 宿主程序；规则示例只有 `web/funroute-examples.json` 一份，工作台、语言服务测试与 `tests/conformance` 都读它 | 一份示例三处使用，不会漂移 | 另存一份一致性用例文件 |
| 数据上没有答案（越界、缺键、空数组、长度对不上、重复键）是 `ErrDomain`；数值参数超出取值范围仍是 `ErrArithmetic`；栈深超出 `MaxStack` 是 `ErrFuel`。运行时错误都有类别 | 内核的这类错误原本没有类别（`fallback` 不接），std 的同类错误却被包成 `ErrExtension` 而被接住，同一件事两种结果 | 并入 `ErrArithmetic`（类别的含义变宽）；维持无类别（std 无法表达"不接"） |
| 两座 Go 桥各有其位：规划好的 codec 走参数与结果的热路径（unsafe、零分配），反射桥走 `FunctionSpec.Go` 的 `reflect.Call`、handle 与非原生 map；记录与结构体只按一条规则匹配（`structFieldFor`：记录的每个字段都要在结构体里有位置，结构体多出的字段保持零值） | 反射调用本来就要 `reflect.Value`，热路径不能反射；规则不同曾让反射桥悄悄丢字段 | 合成一座桥 |
| Manifest 与 Catalog 分开：Manifest 是能装回注册表的签名数据（`Apply`），Catalog 是给前端的只读说明（语言形式的语法与包裹模板、签名文本） | 方向相反，一种形状只会让两种用途都变差 | 合成一份 |
| 语言形式只有一张表（`languageForms`），节点的 kind tag 说哪些节点是形式、哪些可开关，由测试对照；前端从语法树的 `form` 与目录的 `wrap` 得知一切 | 前端不写语法 | 前端的 `FORM_NODES`/`BLOCKS` |
| `Program` 的批量只有一个入口 `RunBatch(ctx, n, in(i), out(i), opts, failed)` | 一个概念一个入口；请求与结果放在哪由宿主的两个函数说 | `RunBatch`/`RunBatchInto`/`RunBatchFunc` 三种形状 |
| 多个包共用的同一段逻辑只写在 `internal/kit`（错误分类、字符判断、`Map`/`Repeated`/`SortedKeys`、JSON 数字解码），kit 只依赖标准库；只有一个包用的工具留在原包 | 相同逻辑写两份会各自漂移；放在最底层，谁都能用而不引入环 | 每个包各写一份私有小工具；万能 `util` 包收纳"将来可能用到"的函数 |

### 执行

| 决定 | 为什么 | 否决了什么 |
|---|---|---|
| 装载时把验证过的栈字节码翻译成寄存器形式再执行（`machine/lower*.go`、`regvm*.go`）：栈位置 k 在整个程序里是同一个寄存器，只读的常量、参数、局部原地读，只在合流、跳转、调用窗口与写局部之前落到栈寄存器；Artifact 格式与 digest 不变 | 栈 VM 每条指令都在搬值；翻译后费率算式从 143 ns 到 30 ns，循环每个元素从 55 ns 到 5–7 ns，不动 Artifact、验证器与编译器 | 改 Artifact 存寄存器字节码（digest 全变，编译器要重写）；JIT（运行时生成机器码，不跨平台，wasm 做不了） |
| 内核运算按签名换成专用指令（`kernelOps`，只认 `builtin`）：快路径内联；答不出（溢出、除零、越界）时停下来问函数本身，错误逐字相同，`TestKernelOpsAnswerAsTheirFunctions` 在边界值上逐项对照 | 专用指令只写快路径，错误只有一份实现 | 为每个专用指令手写一份错误文案 |
| 窥孔只在翻译器里：比较 + 条件跳转、`==` + 条件跳转、推导式的收集 + 下一轮、内层推导直接写外层的数组、结果直接写进局部 | 编译器与字节码保持朴素，指令集不为性能膨胀 | 在编译器里发融合指令 |
| fuel 按基本块在入口一次扣完：块的成本是块内每条指令 1 加调用的 `Doc.Cost`，跑完的程序总量与逐条扣分毫不差；不够时在块入口报 `ErrFuel`，报的位置用逐条扣的规则在块内重算；`fallback` 候选区里宿主调用之后另起一块，接住失败时退回块里没跑到的部分 | 每条指令一次比较与减法是循环里最大的固定开销 | 逐条扣 |
| 函数可声明 `FunctionSpec.Fold`（`Step` 内核函数、`Init`、bool 的 `Stops`/`Stop`、`Counts`）；编译器只认这个声明，把它套单子句推导式的调用编成单遍折叠：`loop_fold` 用 `Step` 把元素并进答案，与 `loop_collect` 同价；`loop_break` 在停止元素处结束循环。std 的 `sum`、`any`、`all` 与内核的 `len` 声明它 | 不建中间数组、不把数组交给函数；每个元素的 fuel 与收集时相同，跑完的程序只会更省 | 按函数名识别聚合；把 `sum` 等并进内核 |
| `any`/`all` 套推导式时在决定答案的元素处停止（语义变化） | 与 `||`、`&&` 一致：`any([10 / x > 2 for x in xs])` 不会在第一个真之后再除零 | 为保持旧语义先算完全部元素（融合就只能省掉数组） |
| 融合后 `sum` 的溢出报 `add` 的错误（类别同为 `ErrArithmetic`） | 折叠的一步就是 `add` | 为折叠另注册一份带 `sum` 文案的步骤函数 |
| `min`/`max` 暂不融合 | 需要"首个元素作种子、空数组报 `ErrDomain`"，现有的 `Fold` 与指令表达不了，且报错位置会变 | 用 `MaxInt64`/`+Inf` 作种子（字符串没有，空数组的错误也丢了） |
| 循环不变量只外提一种：嵌套推导式（外层没有筛选）的内层源不读外层的名字、只调用可折叠的函数时，放到外层 `loop_init` 之后、循环体之前算一次 | 它本来就是每一轮最先求值的东西，外层非空时才算，顺序与失败都不变；外层只有一个元素时多付 2 点 fuel | 一般的循环不变量外提：会让本不求值的表达式被求值（筛选掉的元素、`if` 的另一支），改变失败行为 |
| std 的 `sort` 在没有"相等却可区分"的元素时用 `slices.Sort`，有（float 的 0 与 -0）才用稳定排序 | 相等的 int、string 不可区分，稳定性不可观测；与 Go 同速 | 一律稳定排序（慢 3 倍） |
| 批处理里共用同一个 `ctx` 的请求只注册一次 `context.AfterFunc`；请求结构池化，完成通道不池化 | 语义不变；通道属于创建它的 synctest bubble，不能跨测试复用 | 不再监听请求的取消（改变语义） |

### 语言服务与工作台

| 决定 | 为什么 | 否决了什么 |
|---|---|---|
| Go 只做语言：词法、语法、推导的判断原样交出（语义标记、区间、类型），不输出颜色、布局、控件与文案 | 语言事实只有一份，前端不会与之漂移 | 在 JS 里重写一遍打印、高亮与作用域（曾经这样做，两份实现漂移且各有 bug） |
| 对外接口是 LSP，同一份代码走 stdio 与 WebAssembly | 标准协议划清了语言与界面的边界；专有能力用 `funroute/*` 请求与命令补充 | 自定义 HTTP API |
| 工作台是文本的投影：结构视图的每处修改都是对原文某个区间的替换，前端不理解 ExprJSON | 切换视图不会改写用户写下的文本 | 画布直接编辑 AST |
| 前端依赖只在前端（Lit、CodeMirror）；产物构建而不提交，Go 仍零依赖 | 只用 Go 的宿主不受前端影响 | — |
| 签名清单：没有实现的宿主函数只登记签名，调用得 `ErrUnavailable` | 浏览器里跑不了宿主的模型，但检查、补全、悬停照常可用 | 在语言服务里链接宿主实现 |

## 性能基线

### 寄存器 VM 前后（2026-09-25，Apple M5，Go 1.26；完整对照见 `docs/perf.md`）

| 场景 | 栈式 VM | 寄存器 VM | 原生 Go |
|---|---|---|---|
| `amount * bps / 10000 + fixed`：`RunValues` / `Program.Run` / `Run(map)` | 143 / 198 / 195 ns | 30 / 43 / 52 ns | 1.8 ns |
| 按 Go 签名注册的宿主函数调用 | 307 ns · 5 次分配 | 49 ns · 0 次 | 1.7 ns |
| 500 元素 `reduce` / 推导式 | 27.3 / 27.9 µs | 2.4 / 3.5 µs | 0.13 / 0.47 µs |
| 500 对嵌套推导式（25 × 20） | 39.7 µs · 108 次分配 | 4.9 µs · 8 次 | 0.49 µs |
| `sum([x * 2 for x in xs if x % 3 == 0])`，每个元素 | 121 ns | 14 ns | 2.4 ns |
| `{string(x): x for x in xs}`，每个元素 | 249 ns | 106 ns | 82 ns |
| `sort(xs)`，每个元素 | 170 ns | 54 ns | 53 ns |
| 64 条一批的模型调用，折合每条 | 1.5 µs · 11 次分配 | 0.86 µs · 5 次 | 0.42 µs |

- 与 expr v1.17.8 的旧对照（2026-09-22，栈式 VM）：费率算式 expr 48 ns · 3 次分配，我们 168 ns；现在的 30 ns 未与 expr 同机重测。复现方法：另建一个 module，`replace funroute => ../funroute` 并 require expr，对同一组表达式各写一份（对照基准依赖 expr，不进这个零依赖仓库）。
- 剩下的差距多在 VM 之外：推导式结果的切片装进 `Value` 要装箱一次；`take`、`slice` 等返回切片的 std 函数仍走反射；record 进出每个 record 一次分配。

### 金额

- 未用金额的程序不受金额能力影响：`BenchmarkCall`、`BenchmarkDispatch`、`BenchmarkRunPaths`、向量透传与引入金额前一致。
- 金额运算、换汇与 `using` 都是 0 次分配（`TestMoneyRunsDoNotAllocate`、`TestProgramMoneyDoesNotAllocate`、`TestAConversionAllocatesNothing`、`TestAUsingAllocatesNothing` 守着）。
- `BenchmarkMoneyFee`（费率加固定费再封顶）因多一次 `round` 调用，比每步舍入的旧实现慢约 5%。

## 拆出去单独做

- **汇率的买入价与卖出价、按时点取汇率**：现在一对货币只有一个报价，时效由宿主在传参前决定。若要由语言判定，需要确定性的"当前时刻"作为运行参数。
- **放宽币种代码与小数位**：以数字开头的代码（`1INCH`）、超过 8 位小数。18 位小数的链上资产放不进 int64 最小单位，需要另一种金额表示。
- **复利与利息**：比例的幂会迅速超出 int64 分子/分母，要先定舍入点与精度。
- **字典推导的多个 `for`**：要先定重复键的含义。
- **float 相等警告**：要先有警告通道（编译结果带 warnings，LSP 用 Warning 级别）。
- **`date` / `timestamp`**：时区与 `now` 作参数，保持纯函数；表示方式与时区数据怎么带另议。

## 明确不做

| 不做 | 原因 |
|---|---|
| 张量与 float32 类型 | 句柄替代：形状、dtype、批维度都归引擎 |
| lambda、递归、语言内状态与循环 | 破坏必然终止与成本上界 |
| `nil`、`??`、`?.` | 引入 null 就引入静默传播 |
| `$env`、未定义变量 | 运行时才发现缺参数，等于放弃 digest 的意义 |
| 动态 `type()` | 类型在编译期已定 |
| 正则 `matches` | 成本不可静态估计（ReDoS 击穿多项式上界）；确需时做成注册时预编译、输入限长的扩展函数 |
| `toJSON`/`fromJSON`、base64、bytes、位运算 | 序列化与字节处理归宿主 |
| pipe `\|`、方法调用链、`let … in` | 只是写法偏好 |
| `zip`、左连接式的 `join` | `zip` 的配对要有字段名，写 `{channel: channels[i], fee: fees[i]}` 更清楚；左连接需要"空" |
| `combinations`、`permutations` | 结果规模是阶乘级 |
| `$` 等币种符号 | 币种就是代码：`USD 1.70` |
| `[][]float64` 之上的专用嵌套类型 | 反射转换已覆盖 |

变参函数优先级最低，暂缓。
